Upload Schedule & Cron Health

Each account uploads 3 times a day. For every slot pick Window (bot uploads at one random minute between your From and To times, picked fresh each day) or Exact (the bot starts ~6 min early and holds the Publish click until that minute sharp; change the lead via Firebase dashboardSettings/schedule/exactLeadMin, 0-25). The bot reads these from Firebase, so you can change them here any time - no need to touch cron-job.org or GitHub. Set every cron-job.org job to 0,30 * * * * (Asia/Dhaka); the bot's gate decides when to actually run and catches up if a ping was missed.

Mix Mode — 3 slots, 3 different content types

OFF (default): the bot keeps the normal rotation - one content type per day (Ringtone day, Wallpaper day, 24H set day ...). ON: the 3 daily upload slots of that account each upload a different content type (e.g. slot 1 Ringtone, slot 2 Wallpaper, slot 3 Live wallpaper). The order rotates every day, a type with no queued file is skipped for the next one, and pinned items always win. Gap fill: if only some types have files (e.g. 2 types, 3 slots) the remaining slot is filled with the least-used type that still has stock - 3 slots always mean 3 uploads. Saved per account in Firebase (dashboardSettings/variety) - the bot reads it on every run.

Pinned Files (date overrides)

Pinned files skip the rotation and upload on the exact day you chose (overdue pins run today, first). Change the date inline, or unpin to send a file back to its own content-type day.

Pin a Queued File

Every unpinned file shows its Auto date - where the rotation will place it (or "waiting for stock" if its type has fewer than 3 files). Pick a date and press Pin to override.
